# back-button-and-chrome-simplify Feature PRD

## 背景与变更动机

用户实测走查反馈三项：

1. **底部状态栏疑似多余**：单图模式下其内容（名称/大小/尺寸/序号）与右侧详情栏完全重复；图库模式下显示的是残留的最后一张单图文案（切模式不清），观感"被右栏替代 + UI 重叠"。
2. **单图详情页缺返回按钮**：只能点工具栏"返回图库"，不符合"左上角返回"的操作习惯（Esc 路由存在但不可发现）。
3. **「清除选择」按钮多余**：默认单选模型下"正常点击一张卡即变单选"已覆盖清除场景（Explorer 习惯），按钮占 UI 位置。

## 范围说明（相对原需求）

- 删除底部状态栏组件：其独有的 4 类信息（批量重命名回执、删除/移动/加载失败提示）迁入既有 InfoBar 体系——遵循"成功静默、仅失败弹"口径（selection-and-zoom-polish 已确立）。扫描进度本就走图库状态行，无丢失。
- 单图视图新增左上浮层"◀ 返回图库"按钮（与 Esc 等效；无图库时禁用灰态）。
- 移除图库状态行「清除选择」按钮（上一敏捷项刚加，用户权衡后撤销）——Esc 清空与"点击即单选"已够。

## 影响模块与接口

| 模块 | 变更 |
|------|------|
| MainWindow.xaml(.cs) | 删状态栏行与 Row3；删 BottomChromeHeight 避让链；状态行还原纯文本 |
| ViewModels/MainViewModel | 删 StatusText 属性及 7 处写入（4 类独有信息迁 InfoBar）；删 HasSelection/ClearSelection 命令 |
| Views/SingleImageView(.xaml.cs) | 新增 BackToGalleryOverlay 浮层（左侧动态让出左栏宽度，随左栏收展跟随）；ApplyChromeInsets 扩展 |

## 验收标准

- [x] 单图/图库模式底部均无状态栏；文件名栏贴底不再被压。
- [x] 批量重命名（标签重命名/删除级联）失败时 InfoBar 弹 Warning 聚合回执，全成功静默；删除/移动/加载失败即时 InfoBar 提示。
- [x] 单图视图左上角"◀ 返回图库"：有图库可点返回（raw 鼠标路径验证命中），无图库禁用灰态；随左栏收展左右跟随；工具栏"返回图库"与 Esc 保留。
- [x] 图库状态行无清除选择按钮（纯"共 N 张 · 已选 N 张"文本）；选择语义不变；Esc 清空保留。
- [x] 71 项 Core 单测全绿，build 通过。
- [x] 单图底部文件名栏亦移除（用户复查补充反馈 06b8811）：文件名由右栏信息区承载（含完整名 tooltip），demo 顶部文件名区同步删除。

## 测试用例

1. CLI 直开单图：无状态栏、返回按钮禁用灰态、位置在左栏右侧工具栏下方（实机通过）。
2. 打开图库→双击进单图→raw 点击"◀ 返回图库"→回瀑布流且滚动/选中保留（实机通过）。
3. 图库状态行无按钮；点卡片"已选 1 张"文本正常（实机通过）。
4. 重命名失败回执/删除失败提示迁 InfoBar（代码审查通过，失败路径难自动化构造留用户实机）。
