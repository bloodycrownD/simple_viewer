# drag-visual-thumbnail-and-overlay-canvas Feature PRD

## 背景与变更动机

用户实机走查反馈三个问题：

1. **拖拽视觉**：拖拽图片卡片到左侧标签打标时，跟随鼠标的是整张卡片快照（缩略图+文字区+边框+角标半透明渲染），而非常规图库软件的"小缩略图随鼠标"体验。
2. **首次收展闪跳**：展开/收起左栏或右栏的"第一次"，图片有明显的刷新感（闪一下）。此前 579f33e 已修过"同图重载不预清空"（消灭清空→空白窗口），但首次仍闪。
3. **收展改变图片位置**：展开/收起导致图片显示区域尺寸变化，图片重新适配居中——位置随收展移动，体验割裂。

用户拍板方向：把画布放最底层铺满整窗，侧栏/工具栏等全部作为画布之上的遮盖层（overlay），而非与画布组件同级占位——收展只改变遮盖范围，图片位置天然不动。

## 现象根因（探索结论）

- **拖拽视觉**：卡片 `CanDrag="True"` 但从未定制 DragUI，WinUI 系统默认渲染被拖元素整体快照。
- **首次闪跳**：收展 → ImageHost 尺寸变化 → 解码尺寸变化 → 触发重载。首次该解码尺寸在解码缓存（LRU 容量 6）必 miss，走磁盘 IO+WIC 数十至数百 ms；期间旧源先在新区域 Uniform 拉伸重布局、新源就绪后一次性换上——感知为"动一下/闪一下"。第二次起 LRU 命中一帧完成，故只有第一次闪。
- **位置移动**：ImageHost 尺寸变化的必然结果（图片按新区域重新适配居中）。

## 范围说明（相对原需求）

- 属于"图片打标签与瀑布流浏览"迭代内交互打磨，不改变父级 PRD 任何验收口径。
- 布局语义变化（用户已拍板接受）：单图按整窗适配居中，侧栏展开时图片左右边缘会被侧栏遮盖（遮盖式而非让位式）；换取"图片位置永不因收展而动"。
- 附带修复：GIF 在窗口 resize 触发的同图换源空窗（换源等 ImageOpened 再提交，旧源等待期保持显示）。

## 验收标准

- [ ] 拖拽卡片到标签时，跟随鼠标的是 ~120px 小缩略图（指针居中），不再是整卡快照。
- [ ] 多选拖拽（N>1）悬停标签行时显示"打标 N 张"计数提示。
- [ ] 展开/收起左栏/右栏任意次（含第一次），图片位置与缩放完全不动（画布几何恒定）。
- [ ] 图片按整窗适配；侧栏展开时侧栏区域遮盖图片边缘（遮盖语义）。
- [ ] 图库模式布局不变（左栏让位占位、瀑布流正常）；双模式切换正常。
- [ ] 放大后画布盖过侧栏/工具栏/状态栏（置顶层级不变语义），复位还原。
- [ ] GIF 窗口 resize 时不再闪空（换源等 ImageOpened）。
- [ ] 71 项 Core 单测全绿，build 通过。

## 测试用例

1. 单图模式：收起左栏 → 图片 bounds 不变；展开 → 不变；右栏收起/展开同理（UIA bounds 断言，已实机通过）。
2. 图库模式：打开图库显示瀑布流（占位布局不变），双击进单图（已实机通过）。
3. 拖拽视觉与多选 caption：环境无法注入拖拽手势（RULE 实锤），留用户实机验证。
4. GIF resize：窗口拉伸后 GIF 保持旧源显示直到新源打开完成。
