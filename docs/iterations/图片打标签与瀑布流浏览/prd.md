# 图片打标签与瀑布流浏览 PRD

## 背景

SimpleViewer（WinUI 3 版）当前是一个单目录单图查看器：工具栏 + 单图视图 + 状态栏的三段式布局，核心能力为目录内自然排序翻页、旋转、回收站删除、快捷键"分类归档"（移动到预设文件夹）、可视化快捷键配置与命令行唤起。上述能力已全部交付（迭代 SimpleViewer-WinUI3，见 `.apm/kb/docs/Iterations/SimpleViewer-WinUI3/`）。

用户现有新诉求：为本地图库（约几十万张图片）打标签，采用 **TagSpaces 协议的文件名标签模式**（标签内嵌于文件名尾部方括号，如 `photo[风景 已修].jpg`）——标签数据完全随文件本体走、**不产生任何额外文件**、拷贝移动即随行；标签需支持**互斥标签组**与**非互斥标签组**两种语义；浏览形态从单图升级为**瀑布流排布**（用户明确偏好，认为比规整网格好看）；标签管理入口放在**左侧标签栏**（支持添加、重命名、删除）；整体 UI 风格要求更优雅。

与现状的关系与边界修订：
- 本 PRD 将应用从"单图查看器"演进为"带标签的图库浏览器"，历史 PRD 中"不包含底部缩略图条/胶片条"的边界继续有效（瀑布流是主浏览视图，不是单图模式的附属条）；
- 历史"分类归档 = 快捷键移动文件夹"能力**保留并存**，与"打标签"是两种互补的整理范式；
- 术语消歧：本文所有"标签"均指 tag（TagSpaces 语义），与旧文档中"标签页"（tab，多标签页，仍不做）无关。

## 目标（含成功指标）

1. 用户可以在几十万张量级的本地图库中高效完成图片整理：浏览 → 打标签 → 按标签筛选定位。
2. 标签数据完全遵循 TagSpaces 协议落盘：用 TagSpaces 桌面版打开同一目录，能正确读到本应用写入的标签（互通性验收）。
3. 互斥标签组的语义可靠：同一互斥组内，一张图片任意时刻最多只有一个该组标签。
4. 性能不因量级崩坏（成功指标见"验收标准·性能与规模"）。
5. UI 达到 Win11 Fluent 风格走查通过（对齐旧迭代验收口径）。

## 用户与场景

单用户（作者本人），Windows 11，本地图库约几十万张图片，分布在目录树中。

- **场景 A｜批量整理**：打开图库根目录，瀑布流快速滚动浏览，对图片（单张或批量多选）打标签；星级/状态类标签用快捷键高速处理。
- **场景 B｜筛选定位**：在左侧标签栏点选标签（或标签组），瀑布流即时只显示命中图片；清空筛选恢复全库。
- **场景 C｜精看单图**：从瀑布流进入单图查看（复用现有翻页/旋转/全屏能力），处理后返回瀑布流。
- **场景 D｜存量兼容**：图库中已存在的文件名内嵌标签（TagSpaces 或其他工具写入的 `[tag]` 形式，若有）被正常解析并进入左栏聚合。

## 范围

### 包含范围

- TagSpaces 文件名标签模式的读取与写入（标签内嵌于文件名尾部方括号，增删标签通过重命名文件完成，不产生额外文件）。
- 标签组模型：组可配置为互斥（组内单选）或非互斥（组内多选）；组与标签由用户在左侧标签栏管理（添加 / 重命名 / 删除）。
- 瀑布流浏览视图：递归扫描图库根目录、虚拟化滚动、按需加载缩略图；与单图查看模式双向切换。
- 多选与批量打标：瀑布流内多选（点选 / 连选），将选中集打上或移除标签；批量操作有进度与结果反馈。
- 标签筛选：左侧标签栏点选标签过滤瀑布流内容。
- 设置扩展：标签组配置（含互斥属性）持久化。
- （2026-09-19 CR 修订）未分组标签忽略口径：侧栏聚合 UI 忽略不属于任何配置组的标签（不设"未分组"虚拟组），文件名中实际存在的无组标签不受影响、不丢数据；清理出口 = 单图详情页标签 chips ✕ 逐图移除；在新组新建同名标签即按文件名平铺协议视为同一标签完成收编（敏捷留痕 features/ungrouped-tags-ignore）。

### 不包含范围

- TagSpaces sidecar JSON 模式（`.ts` 目录元数据文件；用户已拍板选择文件名模式且明确不要额外文件，故不读取也不生成 sidecar）。
- 拖拽打标（后续版本可加，本期用点击与快捷键）。
- 全文搜索、OCR、智能文件夹、颜色查找等检索方式（仅标签筛选）。
- 云同步、在线图库、多人协作。
- 视频及其他非图片素材格式。
- RAW 及 png/jpg/jpeg/gif 之外格式的支持（维持历史拍板；见风险与待确认项）。
- 多窗口、多标签页（tab）、图片编辑（沿用历史边界）。

## 核心需求（3-7 条）

1. **TagSpaces 文件名标签读写**：图片标签内嵌于文件名尾部方括号（TagSpaces filename tagging 语法：`原文件名[tag1 tag2].扩展名`，多个标签以空格分隔），全部增删改通过**重命名文件**完成，不产生任何额外文件；读取时解析图库内全部文件名的标签段并聚合进左侧标签栏。标签名不得包含空格（含全角空格等任何空白字符）与方括号（新建/重命名时校验）。文件名展示规则：瀑布流卡片与单图模式统一显示剥离方括号标签段的显示名，完整文件名经 tooltip 呈现（2026-09-19 CR 修订，原"单图模式显示完整文件名并高亮标签段"口径已随底部文件名栏移除调整）。
2. **标签组与互斥语义**：标签必须归属标签组，组属性含"互斥/非互斥"。对图片添加某互斥组标签时，自动移除该图同组已有标签（enforcement 对用户透明）；非互斥组内可叠加多个标签。组的互斥属性可随时切换，切换不改动已落盘标签，仅影响后续交互行为。
3. **左侧标签栏**：常驻左侧的面板，按组展示标签（组名 + 组内标签）。支持：新建组/标签、重命名组/标签、删除组/标签。重命名标签 = 全库更新所有引用该标签的文件名（执行前告知影响数量）；删除标签 = 从所有引用它的文件名中移除（同样先告知范围）；删除组 = 级联移除该组全部标签（先提示影响张数），均不删除图片本体。点击标签 = 作为筛选条件；再次点击 = 取消。
4. **瀑布流浏览视图**：应用的主浏览视图。通过工具栏"打开图库"按钮选定图库根目录后递归扫描并进入瀑布流（CLI 唤起与双击文件直开单图均不自动扫描所在目录，以保冷启动 ≤2s，用户可手动"打开图库"指向该目录；首次启动无图库时瀑布流区显示空态引导文案）。图片按瀑布流（多列、按原始宽高比排布、列高均衡）呈现；滚动虚拟化（只渲染可见区域），缩略图按目标尺寸解码、异步加载、有占位状态。提供与单图查看的切换：瀑布流中双击（或回车）进入单图，单图模式 Esc（或快捷键）返回瀑布流。
   （2026-09-19 CR 修订补记增量能力：启动自动恢复上次图库根目录——设置新增 LastLibraryRoot 持久化，重开应用自动续开上次图库，用户拍板保留；兼容说明见 spec。）
5. **多选与批量打标**：瀑布流支持单选、Ctrl 加选、Shift 连选、全选，Esc 清空当前选中；对选中集点击左栏标签即批量添加（互斥组按语义替换）；支持"从选中集移除某标签"。批量操作展示进度，结束后回执成功/失败数量与原因。单图模式保留快捷键打标能力（如数字键快速打星级类标签，沿用现有"命令 + 参数"快捷键体系）。
   （2026-09-19 CR 修订：①"从选中集移除某标签"收窄——批量移除入口不做：移除走单图详情页标签 chips ✕ 逐图移除，或在正式组新建同名标签把存量无组标签收编后统一管理，用户拍板接受收窄；②批量回执口径改为——进度保留、全部成功静默（就地反馈已充分），仅失败/部分失败弹出终态回执（含失败数量与原因，明细可展开）。）
6. **标签筛选**：左栏可同时激活一个或多个标签筛选（多标签的与/或逻辑需在交互上明确可见，默认"任一命中"）；筛选状态下瀑布流仅显示命中图片，标题区显示当前筛选条件与命中数量，可一键清空。
   （2026-09-19 CR 修订：①一键清空按钮已移除——取消筛选的等效路径 = 二次点击标签（唯一选中时取消）/ 筛选条 chip ✕ 单删 / 无标签按钮二次点击，用户拍板；②增量能力补记"无标签筛选"（untagged-filter-entry）：侧栏标题行 ∅ 入口，激活后只显示无任何标签的图片，与标签筛选互斥（点标签自动退出、激活清空标签集），参考 Billfish，敏捷留痕 features/untagged-filter-entry。）
7. **设置扩展**：AppSettings 升级（Version 2），新增标签组配置（组、成员、互斥属性）；升级对旧 settings.json（Version 1，仅快捷键）保持向后兼容，无损迁移。

## 验收标准

### 标签读写与互操作
- [ ] Given 图库中一张无标签图片 `sunset.jpg`，When 对其添加标签"风景"并完成，Then 文件被重命名为 `sunset[风景].jpg`（TagSpaces 文件名标签语法），目录内不产生任何额外文件，图片内容不变。
- [ ] Given 已带标签的 `sunset[风景].jpg`，When 再添加标签"已修"，Then 文件名变为 `sunset[风景 已修].jpg`；移除标签"风景"后变为 `sunset[已修].jpg`；移除全部标签后恢复为 `sunset.jpg`。
- [ ] Given 本应用打标后的图库，When 用 TagSpaces 桌面版（配置为文件名标签模式）打开，Then 标签被正确识别显示。
- [ ] Given 图库中已有 `[tag]` 形式的存量文件名（TagSpaces 或其他工具生成），When 本应用打开图库，Then 标签被解析并出现在左侧标签栏，且可正常增删。
- [ ] Given 带标签文件名 `sunset[风景 已修].jpg`，When 在瀑布流与单图模式中展示，Then 瀑布流卡片与单图模式均剥离方括号标签段（显示 `sunset`），完整文件名经 tooltip 呈现，标签信息在标签区域呈现。（2026-09-19 CR 修订口径，原"单图显示完整文件名并高亮标签段"废止）

### 标签组与互斥语义
- [ ] Given 互斥组"状态"（成员：待筛选/已选中/已废弃），图片已有标签"已选中"，When 添加同组标签"待筛选"，Then 该图标签变为仅"待筛选"（文件名落盘结果一致）。
- [ ] Given 非互斥组"主题"（成员：海/山/城市），When 依次添加"海"和"山"，Then 两标签并存。
- [ ] Given 任意互斥组，When 检查任意单张图片，Then 其同组标签数量 ≤ 1（批量操作、快捷键打标、重命名等一切入口均满足）。
- [ ] Given 已有标签的互斥组被切换为非互斥（或反之），When 切换完成，Then 已落盘标签不变，仅后续交互行为按新属性执行。

### 左侧标签栏
- [ ] Given 左栏，When 新建组并添加标签、重命名组/标签、删除组/标签，Then 操作生效且配置持久化（重启后保持）。
- [ ] Given 标签"风景"被全库 1000 张图片引用，When 重命名该标签，Then 应用先提示影响 1000 张，确认后全部文件名更新完毕，TagSpaces 中读到的即新标签名。
- [ ] Given 删除某标签（被 100 张引用），When 确认执行，Then 100 张图片的该标签被移除，图片文件本体完好。
- [ ] Given 左栏点击标签"海"，When 瀑布流刷新，Then 仅显示含"海"的图片且显示命中数量；再次点击恢复。

### 瀑布流与视图切换
- [ ] Given 打开图库根目录（含子目录），When 扫描进行中，Then 已发现的图片即开始以瀑布流呈现（无需等全量扫描完成），扫描进度可见。
- [ ] 瀑布流默认按"发现顺序"排列：打标导致的文件重命名不引起图片位置跳动；本期不提供排序切换。
- [ ] Given 瀑布流中不同宽高比的图片混合，When 排布渲染，Then 呈多列瀑布流形态、缩略图保持原始宽高比、滚动时不错位不跳动。
- [ ] Given 瀑布流中任一缩略图，When 双击，Then 进入单图查看；单图模式下按 Esc，Then 返回瀑布流且滚动位置保持。
- [ ] Given 现有单图能力（翻页/旋转/全屏/删除/分类归档移动），When 在单图模式使用，Then 行为与现状一致（回归）。

### 批量打标
- [ ] Given 瀑布流中 Ctrl/Shift 选中 100 张，When 点击左栏非互斥标签"海"，Then 100 张全部新增该标签，进度可见，完成后回执成功数。（2026-09-19 CR 修订：全部成功时静默不弹——就地反馈已充分，仅失败/部分失败弹终态回执；批量进度保留）
- [ ] Given 选中集中部分文件重命名失败（如文件被占用），When 批量操作完成，Then 回执明确失败数量与原因，成功部分不回滚。
- [ ] Given 选中集已带互斥组标签，When 批量打入该组另一标签，Then 全部选中图片按互斥语义替换成功。
- [ ] Given 单图模式，When 使用快捷键打标签（如星级），Then 当前图片立即生效并落盘。

### 性能与规模
- [ ] Given 约 5 万张图片的目录，When 打开后浏览，Then 首屏瀑布流呈现 ≤ 3 秒，滚动过程 UI 不冻结、缩略图异步渐入。
- [ ] Given 几十万张图片的图库（目录树），When 首次全量打开，Then 扫描在后台进行、应用全程可操作不假死。
- [ ] Given 约 10 万张命中量的标签筛选，When 点击标签，Then 命中结果首屏呈现 ≤ 2 秒。
- [ ] Given 单张打标，When 操作完成，Then 反馈延迟 ≤ 1 秒（不含批量）。
- [ ] 同目录单图切换体感 < 100ms、冷启动 ≤ 2s（本期口径）。
- [ ] Win11 Fluent 风格走查通过（瀑布流、左栏、对话框、深浅色主题）。

## 风险与待确认项

以下决策点在澄清阶段未获用户明确答复，本 PRD 采用括号内默认值落盘，**确认时可逐项推翻**：

1. **标签存储模式**（已拍板 2026-09-16：**文件名内嵌 `[tag]` 模式**，用户明确不想要额外文件；sidecar 模式不做，含读取）。随之接受的已知影响：每次打标即重命名文件，图片在文件名自然排序中的位置会移动，`viewer -d -i` 的 1-based 索引在打标后可能漂移，外部按文件名引用图片的脚本会受影响。
2. **图库范围**（默认：打开单个根目录后递归扫描子目录，聚合浏览；不做多根目录"图库"注册概念）——若实际是"多目录分别打开"或"多根目录图库"，范围需修订。
3. **互斥标签组的实际场景**（默认：做成通用"单选组"配置，不预设星级/状态等特定交互控件）——若确认主要是星级类，可引入专用星级控件优化体验。
4. **图片格式白名单**（默认：维持 png/jpg/jpeg/gif 四种，沿用历史拍板）——图库场景下 webp/bmp/avif 等常见格式是否纳入待用户确认。
5. **界面语言**（默认：新 UI 采用简体中文；存量英文文案在本次迭代内一并中文化）——若需保持英文或双语，请指出。
6. **多标签筛选逻辑**（默认：多标签之间"任一命中即显示"的 OR 逻辑）——若需 AND（同时含所有选中标签）或可切换，请指出。
7. **标签组配置存放位置**（默认：全局 `%LocalAppData%\SimpleViewer\settings.json`，随应用不随图库目录迁移）——若希望组配置跟随图库目录（换机器可带走），需改为图库级配置文件。
8. **缩略图与标签索引的本地缓存**（业务上允许应用在本地维护可重建的缓存以达标性能指标；缓存失效或删除后可全量重建，标签事实源始终是文件名本身）——确认无异议。
9. **文件名长度上限**（默认：改名后路径将达到 Windows 长度限制（260 字符）时，阻止该次打标/重命名并明确提示原因）——文件名标签会随标签增多变长，深目录图库需特别注意。
