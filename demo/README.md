# 打标签 + 瀑布流 交互原型

为「图片打标签与瀑布流浏览」PRD 做的纯前端交互原型（HTML + CSS + JS，无依赖、无需构建）。

## 怎么打开

直接双击 `index.html`（或拖进浏览器）。图片来自 picsum.photos 占位图服务，**需要联网**；离线时会显示彩色渐变占位块，不影响交互验证。

右上角「重置数据」可清空本地改动重新开始。

## 覆盖的 PRD 行为

| 模块 | 交互 |
|------|------|
| 瀑布流 | 多列、按图片宽高比排布；打开时模拟"递归扫描渐进呈现"（顶部可见扫描进度） |
| 文件名标签协议 | 打标即"改名"：单图查看页可见完整文件名 `sunset[风景 已修].jpg`（标签段高亮）；瀑布流中文件名展示剥离标签段 |
| 左侧标签栏 | 按组展示；组可新建/重命名/删除/切换互斥⇄多选；标签可添加/重命名（提示影响张数）/删除 |
| 互斥组 | 组内单选：打新标签自动替换同组旧标签（toast 有提示）；chip 带单选圆点样式 |
| 批量打标 | 选中图片（单击/Shift 连选/Ctrl+A）后点击左栏标签 = 批量打标；Shift+点击标签 = 批量移除 |
| 标签筛选 | 未选中时点击标签 = 筛选（多标签 OR 语义）；筛选条显示条件、命中数，可单删/清空 |
| 单图查看 | 双击缩略图进入，←/→ 翻页，Esc 返回；可在单图页直接点标签打标 |
| 排序 | 顶部可切换"按文件名（含标签）"与"按发现顺序"——**前者打标后图片位置会跳动**，这是文件名标签模式的固有代价，建议实际体验一下能否接受 |

## 有意为之的简化（与真实应用的差距）

- 不真的读写磁盘文件，"改名"只发生在内存里；刷新后通过 localStorage 恢复标签改动；
- 420 张图全量渲染 DOM，未做虚拟化——真实应用的几十万张需要虚拟化 + 缩略图管线，性能口径见 PRD 验收标准；
- 没有文件被占用、路径超长等失败分支（PRD 中批量操作失败回执在原型中未模拟）；
- 扫描进度、目录树都是模拟数据。
